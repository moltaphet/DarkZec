## 1. OFFICIAL REFERENCES & ECOSYSTEM RESOURCES
- **ZIPS (`zips.z.cash`):** ZIP-321 (Payment URIs), ZIP-316 (Unified Addresses), ZIP-302 (512-byte Encrypted Memos).
- **Zodl Wallet (`github.com/zodl-inc`):** Primary shielded-by-default mobile UX reference, URI deep-linking, and CrossPay standard.
- **NEAR Intents (`docs.near-intents.org`):** Cross-chain asset settlement solver framework for bridging Shielded ZEC <-> EVM/Solana assets without transparent linkage.
- **Zebra / librustzcash:** RPC querying (`z_listreceivedbyaddress`, `z_viewtransaction`) and viewing key unsealing architecture.

## 2. PRIVACY & ZERO-LEAKAGE INVARIANTS
1. **No Transparent Outputs:** Every refund, deposit, and settlement output MUST use an Orchard receiver in a Unified Address (`u1...` / `utest1...`). Standard wallet UAs containing Orchard plus Sapling/transparent receivers are accepted as input, then projected to an Orchard-only UA for payment instructions. Bare transparent addresses and UAs without Orchard are rejected. Refund and vault MUST resolve to different Orchard receivers, even if their UA strings differ.
2. **Memo Byte Constraint:** All structured protocol data (auction IDs, bid prices, quantities, cryptographic salts) must be packed into JSON and strictly validated to fit under **512 bytes in UTF-8** per ZIP-302 (`TextEncoder().encode().length <= 512`).
3. **ZIP-321 Base64url Compliance:** Memos embedded in payment request URIs must use unpadded Base64url encoding (`+` -> `-`, `/` -> `_`, strip `=`).
4. **Client-Side Sovereignty:** No private keys, spending keys, or seed phrases ever touch external servers. All encryption, salt generation, and commitment hashing occur 100% locally in the browser.
5. **Zero External Network Leaks:** No external CDN font loads (Google Fonts), telemetry, or third-party analytics. Pure local system monospace typography and NODE 07 retro-terminal styling.
6. **Mock-Only Vault Credentials:** Until an audited WASM adapter is ready, the browser vault MUST accept only `mock:node07:` followed by exactly 64 lowercase hexadecimal characters. Real Unified Viewing Keys MUST be rejected before storage access and after decrypting a legacy saved record. The only permitted session persistence is a passphrase-encrypted mock-key record; raw keys, passphrases, bids and logs MUST NOT be persisted.
7. **Readable Terminal Text:** All terminal, telemetry, memo, table and canvas text MUST be at least 12 CSS pixels, including responsive overrides. Primary readouts (inputs, bid values, payloads, result cells and telemetry values/events) MUST be at least 14 CSS pixels. Mobile results MUST remain horizontally scrollable with a visible scroll hint.

## 3. DARK POOL & MERKLE AUDIT SPECIFICATION
- **Commitment Formula (Phase 1 / v2):** `SHA256(UTF8(JSON.stringify(["DARKZEC/bid/v2", auction_id, refund_ua, salt, canonical_price, quantity])))`. The refund UA is normalized to its Orchard-only form during preparation. A canonical typed tuple prevents ambiguous field concatenation; auction context prevents cross-auction replay of the same commitment. Legacy commitments are not accepted for newly prepared memos; the memo schema remains version 1.
- **Tie Priority:** Equal-price bids use accepted submission order. Binding a UA does not prevent grinding a user-controlled salt or prove address ownership. Hash values MUST NOT determine allocation priority. Submission-order priority is not Sybil resistance or decentralized sequencing.
- **Uniform Price:** Eligible demand at or below supply, or a single eligible bid envelope, clears at reserve. With one winning envelope capturing the entire supply, its own excess quantity is excluded from the margin: use the highest losing eligible envelope, or reserve without competition. With multiple winning envelopes, the highest unfilled eligible lot sets the uniform price, bounded below by reserve; a partially filled marginal bid can set that price. The single-lot unit-demand case matches second-price clearing; multi-lot bidding is not claimed to be strategyproof VCG.
- **Commit/Reveal Ledger:** Commit accepts only `{auctionId, commitment, collateral}` with fixed collateral; no preimage enters the ledger. Closing freezes the ordered commitment set and a 60-second reveal window opens. A reveal is valid only if it rebuilds a canonical memo, passes the refund-vs-vault check, recomputes to a recorded commitment and satisfies `price x quantity <= collateral`. Only verified reveals are cleared; every unrevealed commitment forfeits its full collateral as the non-reveal penalty, and that collateral MUST be burned (or otherwise kept from the operator), never credited to the vault operator, who decides reveal validity and could otherwise profit from ignoring reveals or from shill bids it never reveals (settlement of the burn is out of scope for the sandbox). Conservation invariant: payments + refunds + forfeited collateral = all posted collateral.
- **Clearing Mechanism:** Vickrey (Second-Price) or Uniform-Price Batch clearing executed upon unsealing incoming shielded notes via the Vault's Incoming Viewing Key (IVK).
- **Participant Audit:** A public SHA-256 Merkle tree over every accepted commitment, frozen when the commit phase closes (revealed or not), allows any bidder to cryptographically verify their bid was included in price discovery without revealing their identity or bid amount.
- **Operator Statements:** Each auction session signs, with a non-extractable ECDSA P-256 key, canonical typed tuples for close `["DARKZEC/close/v1", auction, root, count, closedAt, revealDeadline]`, every accepted reveal `["DARKZEC/reveal-ack/v1", auction, root, commitment, index, acceptedAt]` and the result `["DARKZEC/result/v1", auction, root, SHA256(canonical result)]`. The acknowledgement is returned to the bidder when the reveal is accepted.
- **Audit Bundle:** After clearing, the operator exports rules, ordered commitments, root, accepted reveals, result and statements. A verifier MUST recompute the root, open every reveal, re-run clearing, check conservation, and verify the close statement, exactly one acknowledgement per accepted reveal inside the window (and none for an omitted bid) and a result signature matching both the published and the recomputed result.
- **Collateral Tiers and Unit Demand:** An auction fixes one collateral tier (1, 10 or 100 ZEC) for every commitment. In unit-demand mode every bid is for one lot and clearing charges the (k+1)-th price, which is truthful; one lot gives Vickrey clearing.
- **Live Testnet Ingestion:** Commits are accepted only from confirmed Orchard notes at the vault carrying exactly the tier and the exact canonical commit memo, ordered by confirmations, oldest first. Reveals are read only after close from reveal-receipt memos and are fully validated by the ledger. The server exposes only read-only `getblockchaininfo` and `z_listreceivedbyaddress` calls; viewing keys and RPC credentials never reach the browser.
